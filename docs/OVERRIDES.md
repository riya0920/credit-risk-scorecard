# ML-3 — the discretionary layer, on real HMDA decisions

Generated by `run_overrides.py` on 26,192 real 2023 Delaware
applications with complete underwriting fields.

## 0. What is actually being measured, before any number

HMDA records what the lender **decided**. It does not record the score,
the cutoff, or whether anyone overrode anything — no public mortgage
dataset does, because override logs are internal. So this fits a model
on the underwriting variables HMDA does carry, calibrates its cutoff so
it approves *exactly as many* applications as the market actually
approved, and examines the applications where the two disagree.

**Those disagreements are not observed overrides.** They are decisions
the fields in this file cannot explain, and the largest single reason
for that is the variable the file does not have: credit score. A real
override log separates *the underwriter used information the model
lacks* from *the model lacks information*. This cannot, so the
disagreement rate below is an **upper bound on discretion** and reading
it as an override rate would be a false claim.

## 1. The model standing in for policy

| | |
|---|---|
| features | `dti`, `ltv`, `income_k`, `loan_amount_k`, `loan_to_income` |
| AUC | 0.7550 |
| market approval rate | 75.49% |
| cutoff, calibrated to that rate | 552.8 |

AUC 0.7550 is a weak model, and that is the honest starting point —
without a credit score these five fields do not separate approvals from
denials well. Every disagreement number below inherits that weakness,
which is why the section above calls them an upper bound.

## 2. How often the decision and the model disagree

| | count | rate |
|---|---|---|
| approved below the model's cutoff (low-side) | 2,945 | 11.24% |
| declined above it (high-side) | 2,945 | 11.24% |
| total disagreement | 5,890 | 22.49% |

The two sides are equal by construction — the cutoff was calibrated to
match the market's approval volume, so every application waved in has
one turned away. That symmetry is a property of the calibration and
carries no information; the distribution of those decisions does.

## 3. Where the line actually sits

| | |
|---|---|
| policy cutoff | 552.8 |
| effective cutoff (lowest 10-point band still approving >=50%) | 380.0 |
| drift | -172.8 points |
| approval rate below the cutoff | 45.88% |
| decline rate above it | 14.89% |

On a book following its own policy these two numbers are the same and
both rates are near zero. In a real deployment a gap means the model was
validated on a population the lender does not actually lend to.

**Here it means something else, and the difference matters.** A drift of
-173 points is not evidence that Delaware lenders ignore their
policies — it is a restatement of the AUC in section 1. When the
stand-in model ranks applicants weakly, its score ordering and the real
decision ordering diverge everywhere, and the divergence shows up here
as drift. `src/overrides.py` flags sustained override rates above
5% because that is where a real policy stops describing a real
book; comparing the 22.49% below against that threshold would be
comparing a model-fit statistic against a governance one.

## 4. Is the unexplained layer evenly distributed?

**This is the question worth asking of real data.** The model uses no
protected attribute. If the unexplained decisions were simply the
credit score this file is missing, they would fall on applicants
roughly in proportion to who applies.

| group | decisions | waved in | turned away | **both** | low-side ratio | high-side ratio |
|---|---|---|---|---|---|---|
| Black or African American | 4,824 | 12.94% | 14.84% | **27.78%** | 1.000 | 0.606 |
| White | 15,476 | 11.56% | 8.99% | **20.55%** | 0.894 | 1.000 |
| not reported | 3,853 | 9.65% | 16.01% | **25.67%** | 0.746 | 0.561 |
| Joint | 528 | 8.33% | 9.47% | **17.80%** | 0.644 | 0.949 |
| Asian | 1,235 | 7.29% | 9.72% | **17.00%** | 0.563 | 0.925 |

Ratios are benchmarked against the best-treated group, matching the
80% rule in `src/fair_lending.py`: most favourable is most waved in and
least turned away.

**3 of 5 groups fall below 0.80 on being waved in, and 2 on being
turned away.** Under the 80% rule that is a screen failure in the
discretionary layer specifically — not in the model, which never saw
a protected attribute.

**Read the `both` column before reading the ratios.** A group with
elevated disagreement in *both* directions is not obviously receiving
more discretion — it is a group the stand-in model fits worse. More
unexplained decisions in both directions is the signature of a
subpopulation whose approvals the five available fields predict poorly,
which is what the missing credit score would do if it is distributed
differently across groups. That is a materially different explanation
from discretion, it is not distinguishable in this data, and a one-sided
reading of the ratio columns would hide it.

On this run the spread runs from **27.78%** (Black or African American) to **17.00%** (Asian) —
a factor of 1.6, and the group at the top has the *highest*
waved-in rate as well as a failing turned-away ratio. That pattern
fits worse model fit at least as well as it fits uneven discretion.

The same caution as everywhere else in this project applies with full
force: this is every lender in the state pooled, the model is weak, and
the missing credit score is correlated with the protected attribute in
the population. A disparity here is a **screen result** — a reason to
pull the real override logs, which is a thing only the lender can do.

## 5. The question this data cannot answer at all

Whether the discretion was *right*. That needs loan performance —
did the waved-in applications repay? — and HMDA has no outcome field.
`override_value` returns:

> no seasoned loans at all -- every approval has defaulted=None, so nothing here can be evaluated and no conclusion is available

and it returns that rather than a number, because a silent zero would
read as *overrides perform in line* when it means *there is nothing to
compare against*. Freddie Mac's Single-Family Loan-Level dataset is free
and does carry repayment outcomes, but it contains only **originated**
loans — no denials — so it can never identify an override either. The
two halves of the question live in two datasets and no public source
joins them.

The counter-intuitive part, recorded because it is where this analysis
would go wrong next: overrides *outperforming* their benchmark is not
good news. It means the underwriters are using a real predictor the
model does not have, and the correct response is to find that feature
and retrain — not to widen the override policy.

## 6. What a real deployment records and this cannot

| field | why it matters | in HMDA |
|---|---|---|
| the score at decision time | recomputing under a later model lets a recalibration retroactively rewrite override history | no |
| model version | same reason | no |
| override reason code | a high-side override with no reason is an adverse action without a documented basis — an ECOA problem before a modelling one | no |
| underwriter id | delegated authority concentrates; one person accounting for a third of low-side overrides is a control finding regardless of performance | no |
| loan outcome | the only way to know whether the discretion was right | no |

All 5,890 disagreements here are undocumented in the reason-code sense,
which is a property of the dataset rather than a finding about any
lender. `src/overrides.py` carries the checks; this file is a
demonstration of them against the most realistic input available for
free, and an explicit statement of what that input cannot support.
