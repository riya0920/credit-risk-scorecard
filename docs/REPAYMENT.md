# ML-3 — a scorecard fitted on repayment, not on a decision

Generated by `run_repayment.py` on 30,000 real credit accounts
(UCI/OpenML default-of-credit-card-clients: Taiwan, 2005, six months of
repayment history and a binary default outcome for the following
month). Held-out test set of 9,000.

## Why a second dataset at all

| | target | what a card fitted on it learns |
|---|---|---|
| HMDA | `denied` — what an underwriter concluded | to imitate the underwriter, including their mistakes |
| this | `default` — what the borrower subsequently did | credit risk |

HMDA records decisions and never records repayment. Every AUC, KS and
PSI figure computed on it in this project is a statement about
agreement with past decisions, and `docs/HMDA_FAIR_LENDING.md` says so.
`run_overrides.py` put the same gap the other way round: *the two
halves of the question live in two datasets and no public source joins
them.*

**Freddie Mac was tried first.** Its Single-Family Loan-Level dataset
is free, carries real repayment outcomes, and requires registering an
account — which is not something to do on somebody's behalf. It also
contains only originated loans, so it carries an outcome and no
protected attributes.

This file carries **both in the same place**, which is the only
configuration in which a fairness metric can be computed against
repayment. It is Taiwanese revolving credit in 2005, not US mortgages
in 2023: nothing measured here transfers to the HMDA population, and
the two are kept in separate documents for that reason.

## The column mapping was verified, not assumed

The file arrives with columns named `x1`..`x23`, `y`. The published
dictionary gives a mapping and this checks it against the data before
relying on it: `x1` spans 10,000–1,000,000 across 81 values (a credit
limit), `x2` is binary, `x5` runs 21–79 (an age), `x6` runs −2..8 (a
repayment status), `x12` goes negative (a bill amount) — and the
resulting default rate is **22.12%**, which matches the published
figure for this study exactly. That match is what confirms the mapping.

## Undocumented codes

The dictionary says EDUCATION takes 1–4 and MARRIAGE 1–3. The file
disagrees:

| column | level | accounts | share | default rate |
|---|---|---|---|---|
| `education_label` | undocumented_5 | 280 | 0.93% | 6.43% |
| `marriage_label` | undocumented_0 | 54 | 0.18% | 9.26% |
| `education_label` | undocumented_6 | 51 | 0.17% | 15.69% |
| `education_label` | undocumented_0 | 14 | 0.05% | 0.00% |

Kept as their own levels rather than folded into *other*. A code nobody
documented is a fact about the data-collection process, and folding it
away destroys the only evidence that it happened — which is exactly the
case `src/categorical.py` was written for. Note their default rates:
they are not interchangeable with each other or with `other`.

## The model

| | |
|---|---|
| features | `limit_bal`, `age`, `utilisation`, `worst_delinquency`, `months_delinquent`, `pay_0`, `pay_2`, `bill_1`, `pay_amt_1` |
| test AUC | **0.7482** |
| base default rate | 22.12% |

### The comparison that inverted

This document first asserted that the HMDA stand-in model scored 0.66
and that a real-outcome model would beat it. Checking
`docs/OVERRIDES.md` rather than remembering it: the HMDA model scores
**0.7550**, and this one scores **0.7482**. The decision model is
*better*.

Which is the more interesting result, and it argues for this dataset
rather than against it. **Predicting a decision is an easier problem
than predicting default.** An underwriter's decision is a largely
deterministic function of the application in front of them, so a model
fitted to it is reverse-engineering a rule. Default is genuinely
uncertain: the same applicant repays or does not, and no feature set
resolves that.

So a high AUC against `denied` is not evidence of a good credit model.
It is evidence that the target was easy — and the easier the target,
the more completely the model has learned to imitate the underwriter
rather than the risk. **Comparing the two AUCs as though they measured
the same thing is the error**, and this document made it before it
looked the number up.

## The question a decision target cannot pose

With a decision target you can measure whether groups are treated
differently. You cannot measure whether they are treated **correctly**,
because there is nothing to be correct about — the target *is* the
treatment. A real outcome separates the two:

### Disparity: does the model decline one group more?


**by `sex_label`** (approving the safest 80% by predicted PD)

| group | accounts | approval rate | **actual default rate** |
|---|---|---|---|
| female | 5,484 | 81.20% | **20.44%** |
| male | 3,516 | 78.13% | **24.74%** |

**by `education_label`** (approving the safest 80% by predicted PD)

| group | accounts | approval rate | **actual default rate** |
|---|---|---|---|
| graduate | 3,226 | 84.87% | **19.19%** |
| high_school | 1,450 | 73.66% | **25.52%** |
| university | 4,179 | 77.99% | **23.83%** |

Adverse impact ratio on sex: **0.9622**

And the actual default rates are 24.74% for men against 20.44% for
women — a real difference of **4.30 percentage points**, in the
data rather than in the model.

### Calibration: is the probability it assigns them right for them?

| group | accounts | weighted abs. gap | signed gap |
|---|---|---|---|
| female | 5,484 | 0.0278 | -0.0114 |
| male | 3,516 | 0.0187 | +0.0109 |

Measured **out of sample**, because a model is calibrated on its own
training data almost by construction and an in-sample calibration
figure is a statement about fitting rather than about fairness.

The gap between the best- and worst-calibrated group is
0.0187 against 0.0278.

### Reading the two together

This is the tension `docs/HMDA_FAIR_LENDING.md` could state and could
not measure. **If a group genuinely defaults more, a well-calibrated
model declines them more, and the AIR falls without anything in the
model being wrong about them.** Equalising the AIR then requires
lending to the higher-risk group at a price that does not cover their
risk.

That is a policy choice somebody should make deliberately, not a bug
to be patched out of a model — and it is only visible at all because
there is a real outcome to check the model against. On a decision
target the same two numbers would be the same number.

## What this does not license

- **Nothing here transfers to HMDA.** Taiwanese revolving credit in
  2005 against US mortgages in 2023. The value is that the target means
  what the word means, not that the population is comparable.
- **Calibration is not sufficient either.** A model can be perfectly
  calibrated within each group and still encode a historical injustice,
  if the outcome itself was shaped by one. Calibration checks the model
  against the world as it is; it cannot check the world.
- **Sex here is binary because the file is.** A two-level protected
  attribute is the easy case and real fairness work is not that.
- **No reject inference.** These are all approved accounts, so the
  default rate is conditioned on someone having already said yes —
  which is the same selection `src/reject_inference.py` exists for, in
  a dataset that cannot correct it.
