# Fair Lending Analysis

> **The protected attribute in this document is SYNTHETIC.** It is generated by `src/generate.py` and correlated with `region_risk` by construction, so that a genuine proxy structure exists to detect. Every ratio below is a property of that construction. Nothing here describes a real population, and presenting these as findings about one would be exactly the control failure this repository is written to avoid.

## Regulatory frame

ECOA / Regulation B (15 U.S.C. 1691; 12 CFR 1002) governs discrimination in credit. Reg B 1002.9 requires an adverse-action notice stating the **principal reasons** for a denial -- which is why the points-lost reason codes in `src/scorecard.py` are a regulatory artifact rather than a modelling nicety.

- **Disparate treatment**: using a prohibited basis as an input, or treating applicants differently because of it. Neither model here takes the attribute as an input, so treatment is not the question.
- **Disparate impact**: a facially neutral policy that disproportionately burdens a protected class, is not justified by business necessity, **or** for which a less discriminatory alternative exists that serves the same purpose. That final clause is analysed in section 5; it is the one most analyses omit.


## 1. Adverse impact ratio at a 80% approval rate

| group | n | approval rate |
|---|---|---|
| 1 | 2,846 | 0.7758 |
| 0 | 4,570 | 0.8151 |

**AIR = 0.9518**, bootstrap 95% CI [0.9291, 0.9740] -> does not flag the 80% rule

The interval is reported because the 80% rule gets applied to a point estimate as though it were exact. An AIR of 0.79 on a thin sample and 0.79 on a fat one are not the same finding.

## 3. Can the model's features reconstruct the protected attribute?

Probe: logistic regression from the model's own features to group membership. **AUC = 0.5935**.

This is the number that decides whether "we do not use the attribute" means anything. At 0.5 the features carry no group information; materially above it, the model can act on the attribute without ever being shown it.


## 4. Proxy ablation

Suspected proxies: `region_risk_proxy_a`, `region_risk_proxy_b` -- two features with ordinary business rationales (a regional risk index and a blended geography/utilisation score) that partially encode geography. This is how proxies actually arrive: nobody adds a prohibited basis, somebody adds a branch-distance feature.

| | full model | proxies dropped | change |
|---|---|---|---|
| AIR | 0.9518 | 0.9880 | +0.0362 |
| group reconstruction AUC | 0.5935 | 0.5165 | -0.0770 |

**18% of the recoverable group signal survives** dropping both proxies.

Dropping the proxies materially improved the AIR, which makes them a genuine driver of the disparity and a live remediation candidate -- weighed against the discrimination lost.


## 5. Less-discriminatory-alternative search

Tolerance (a stated policy choice, not a discovered constant): an alternative qualifies if it raises AIR by >= 0.02 while giving up <= 0.005 AUC.

| candidate | AUC | AIR | AIR gain | AUC cost | verdict |
|---|---|---|---|---|---|
| champion (scorecard, all features) | 0.6674 | 0.9518 | - | - | baseline |
| scorecard_without_proxies | 0.6533 | 0.9880 | +0.0362 | +0.0141 | reduces disparity but exceeds the accuracy tolerance |
| gbm_challenger | 0.6709 | 0.9566 | +0.0048 | -0.0035 | does not reduce disparity materially |

**This is the interesting outcome, so it should not be read past.** `scorecard_without_proxies` reduces the disparity by +0.0362 AIR at a cost of 0.0141 AUC. The stated tolerance is 0.005, so under the policy as written it does not qualify -- but the policy is a number I chose, and a regulator's question would be why 0.005 rather than 0.0141. Answering "our tolerance said no" is not a defence when the tolerance was set by the party whose model is under review. The honest position is that this alternative is live and the tolerance needs an owner outside modelling.


**Conclusion: an alternative DID reduce disparity but exceeded the stated accuracy tolerance -- the tolerance itself now requires justification, and this is not a clean pass.**

Showing business necessity does not end a disparate-impact analysis. If a less discriminatory alternative serves the same purpose comparably well, the original practice remains actionable -- so the search has to be run and recorded even when it comes back empty.


## 6. What this analysis does NOT establish

- **Nothing about any real population.** The attribute is synthetic.
- No causal mechanism. AIR is an outcome ratio.
- No business-necessity documentation for the features that drive the disparity -- that requires the lender's own justification, not the modeller's.
- One binary attribute. No intersectional analysis, no age or marital status, no geography-based redlining analysis.
- Training population is funded loans only, so the disparity measured is conditional on the incumbent's approval policy, which itself may carry impact this analysis cannot see. See reject inference in the README.
